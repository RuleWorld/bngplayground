## 2024-05-18 - Avoid repeated .find() in optimization loops
**Learning:** O(N) array search inside nested optimization loops (e.g. paramFitter) over simulation datasets causes significant performance degradation. The repeated execution of find mapping rows to timePoints can be pre-computed outside the loop to be O(1) inside.
**Action:** Always extract invariant computations outside nested loops during algorithm evaluations. Interpolations over datasets should map the rows once for given times, instead of repeating search across multiple observables within the loops.
## 2024-05-18 - Safe array bounds after optimization
**Learning:** When refactoring O(N) array search functions (like `.find()`) that are executed repeatedly within inner loops to use pre-computed O(log N) binary searches or direct index lookups, ensure that empty array scenarios do not cause regression exceptions (e.g. `simData[0]` throws if `simData` is empty). Additionally, if extracting the bounds-checking out of an inner loop, maintain the safe fallback values so the outer accumulator logic is not accidentally short-circuited.
**Action:** When migrating from `Array.find` or `Array.map` to binary searches, explicitly bounds-check the input array length and wrap block logic to conditionally execute, ensuring the default path emits the expected "not found" value instead of short-circuiting the entire pipeline prematurely.
