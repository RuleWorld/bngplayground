## 2026-07-28 - Sparse Stoichiometry CSR Matrix Generation Optimization
**Learning:** In the `buildCSRStoichiometry` function, building the CSR matrix used an array of `Map` objects (`Map<number, number>[]`) for each species to track column/stoichiometry pairs, which were then extracted, pushed to tuple arrays (`[number, number][]`), and sorted with `O(N log N)`. Because the outer loop iterates linearly over the reaction index (`j`), the column entries inserted for each species are naturally strictly non-decreasing. This means sorting is entirely redundant.
**Action:** By replacing the `Map` objects with parallel standard arrays (`rowColIdx: number[][]` and `rowVals: number[][]`) and aggregating duplicate column indices via a single linear run-length encoding (RLE) pass, we completely eliminate map lookups, tuple allocations, and explicit sorting operations. This brings the time complexity of building the intermediate structure from `O(N log N)` down to `O(N)`, drastically reducing garbage collection pressure and speeding up CSR construction by ~8x on large models. Use this pattern whenever accumulating sequential events into sparse row vectors.
