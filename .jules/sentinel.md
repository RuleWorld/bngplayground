## 2024-05-17 - [Fix arbitrary require in cvode_node VM context]
**Vulnerability:** The CVODE node loader script (`cvode_node.ts`) used `vm.createContext` to execute arbitrary generated loader files but passed the unrestricted, global Node.js `require` function into the sandbox context. This allowed any code running inside the VM to require arbitrary node modules (like `child_process`) and bypass the sandbox.
**Learning:** Node.js `vm` contexts are not secure by default if powerful global objects like `require` or `process` are passed in. Even though the executed script (`cvode_loader.js`) might be trusted (from the build step), passing unrestricted `require` into a sandbox violates defense-in-depth principles and creates an RCE vector if the loader file is ever compromised. Emscripten-compiled WASM wrappers typically only need `fs`, `path`, and `crypto`.
**Prevention:** When executing scripts within `node:vm` that need to load modules, never pass the global `require` object. Always use a strict allowlist (e.g., `new Set(['path', 'fs', 'crypto'])`) wrapped in a `safeRequire` function that explicitly throws an unauthorized error if an unexpected module is requested.
